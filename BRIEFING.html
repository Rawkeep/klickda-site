Design (UI/UX)

FarbweltKlare, moderne Palette; Dark Mode von Anfang an mitdenken

Wirkungmodern, kompetent, effizient
TonalitätSachlich und präzise — Effizienz vor Effekt, Fachsprache erlaubt

Stil-Stufe: ELEGANT — Effekt-Paket

  • Scroll-Reveal: Sektionen blenden sanft ein (design-kit/effects.js, Attribut data-reveal — IntersectionObserver, keine Bibliothek nötig)
  • Hero-Hintergrund: weicher Verlauf oder SVG-Muster statt Stock-Foto (design-kit/backgrounds.css: bg-verlauf / bg-punkte / bg-wellen)
  • Navigation verdichtet sich beim Scrollen (data-nav-shrink)
  • Alle Effekte respektieren prefers-reduced-motion (im design-kit eingebaut)
  • Hintergrund-/Hero-Bilder: lokal, optimiert (WebP/AVIF ≤ 200 KB), sonst SVG-Muster — das LCP-Budget gilt trotz Show
  • Effekte sind Würze, nicht Navigation: Inhalt bleibt ohne JavaScript vollständig lesbar

Branchen-Besonderheiten

  • Onboarding: Time-to-First-Value minimieren — der erste Erfolg zählt
  • Empty States als Anleitung designen, nicht als Sackgasse
  • Docs und Changelog sind Vertrauenssignale erster Klasse

Informationsarchitektur

  • Top-Aufgaben zuerst: die 3 häufigsten Aufgaben in maximal 2 Klicks/Taps erreichbar
  • Navigation flach halten (maximal 2 Ebenen) — Tiefe versteckt Funktionen
  • Benennung in Nutzersprache, nicht in Systemsprache (Card-Sorting mit echten Nutzern)
  • Eine Seite = eine Botschaft + ein primärer Call-to-Action

UX-Patterns

  • Klare Value Proposition — In 5 Sekunden beantwortet der Hero: Was ist das, für wen, warum hier?
  • Ein primärer CTA — Pro Seite genau eine Haupt-Aktion — alles andere ist sekundär gestylt.
  • Social Proof — Referenzen, Zahlen, Logos oder Bewertungen nahe am CTA platzieren.
  • SEO-Grundgerüst — Title/Description je Seite, sitemap.xml, robots.txt, strukturierte Daten (Schema.org), Open-Graph-Tags.

Anti-Patterns

  • ✗ Mehr als ein primärer CTA pro Ansicht — konkurrierende Aktionen entwerten beide
  • ✗ Confirm-Dialoge als Sicherheitsnetz — Undo ist das bessere Muster
  • ✗ Text unter 14 px oder Grau-auf-Grau unter dem Kontrastminimum
  • ✗ Karussells/Slider für wichtige Inhalte — Position 2+ sieht fast niemand
  • ✗ PDF als einzige Quelle für Kerninformationen

Qualitätsattribute (der Architektur-Vertrag)

  1. Skalierbarkeit — Starkes Wachstum erwartet — den Skalierungspfad freihalten.
  2. Einfachheit — Jedes Bauteil, das nicht existiert, kann nicht ausfallen und kostet nichts.
  3. Wartbarkeit — Code wird 10× öfter gelesen als geschrieben — für den Nachfolger bauen.

Go-Live: Sicherheit & Bot-Schutz

Automatische Updates ab Werk

  • Auto-Deploy ab Werk: Merge auf main ⇒ Cloudflare/Pages/Fly deployt automatisch — kein manueller Schritt zwischen Freigabe und live
  • Qualitäts-Wächter als GitHub Action (go-live-kit/qualitaet.yml): Lighthouse-Budget + toter-Link-Check bei jedem PR und monatlich per Cron
  • Versionsstempel im Footer/version.json — jeder sieht sofort, welcher Stand live ist
  • 0 Dependencies im Hausstil = nichts veraltet, nichts wird über Nacht unsicher — die Update-Last liegt bei den Inhalten, nicht beim Code

Monitoring & Alarm

  • Uptime-Wächter ab Werk (go-live-kit/uptime.yml): GitHub Action pingt die Live-URL alle 30 Minuten — fällt die Seite, schlägt der Workflow fehl und GitHub alarmiert per E-Mail; 0 €, kein Dritt-Dienst
  • Alternativ/zusätzlich: Cloudflare Health Checks mit E-Mail-Alarm (im Pro-Tarif) — für Kundenseiten reicht der Actions-Wächter
  • Der Versionsstempel im Footer macht Ausfall-Diagnose trivial: welcher Stand lief, als es passierte?
  • Besucherzahlen ohne Cookie-Banner: Cloudflare Web Analytics aktivieren (cookielos, DSGVO-freundlich, 0 €) — nie Google Analytics als Default
  • Monatsreport ab Werk (go-live-kit/monatsreport.yml): am 1. des Monats automatisch Verfügbarkeit + Ausfälle als Report — 1:1 ans Kunden-Update anhängbar; macht die Wartungspauschale sichtbar

Pflege durch den Kunden

  • Inhalte bündeln: Preise, Öffnungszeiten und Texte in EINER gut kommentierten Datei (daten.js/Abschnitt oben in index.html) — der Kunde ändert eine Zeile, nicht die Seite
  • Ein-Klick-Pflege über die GitHub-Weboberfläche: Kunde editiert die Datei im Browser, speichert — Auto-Deploy schaltet es live (main geschützt: Vorschau/PR zuerst, wenn gewünscht)
  • Ab regelmäßigen Änderungen: Decap CMS nachrüsten (go-live-kit/decap/ — Admin-Seite + fertige config.yml; Login im Browser, kein eigener Server) — Kunde pflegt in Masken statt in Dateien
  • Alternativ Service-Modell: Änderungswunsch per WhatsApp/Mail, online in < 24 h — als Wartungspauschale transparent bepreisen
